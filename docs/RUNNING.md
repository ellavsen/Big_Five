# Как запустить систему

Подробно и по шагам. Если что-то пойдёт не так — раздел «Когда сломалось» в конце,
там разобраны все случаи, которые уже случались.

---

## Коротко: как запускать каждый день

```bash
cd ~/Desktop/Projects/Neuro
./run.sh
```

Одна команда поднимает всё: веб-сервис, HTTPS-туннель, бота. Она же сама вписывает
свежий адрес туннеля в `.env` — вручную это делать больше не нужно.

**Окно не закрывать.** Пока оно открыто — система работает. Закрыли или нажали
`Ctrl+C` — всё останавливается.

Дальше — пишите боту **@akmebobot** в Telegram.

---

## Что именно запускается

Четыре части. Первая поднимается сама при включении компьютера, остальные три —
скриптом.

| часть | что делает | поднимается |
|---|---|---|
| PostgreSQL | хранит профили и разговоры | сама, при загрузке |
| бот | разговор в Telegram | `run.sh` |
| веб-сервис | отдаёт страницу карты | `run.sh` |
| туннель | даёт странице адрес в интернете | `run.sh` |

Туннель нужен, потому что Telegram умеет открывать Mini App **только по `https`**,
а на вашем компьютере страница живёт по адресу `http://127.0.0.1:8000`, снаружи
недоступному. Туннель делает из него временный публичный адрес.

## Первый запуск на новом компьютере

Один раз. Дальше хватает `./run.sh`.

**1. Python 3.12.** Не 3.13 — `python-telegram-bot 20.7` с ним несовместим.

```bash
python3.12 --version    # если нет: brew install python@3.12
```

**2. PostgreSQL и база.**

```bash
brew install postgresql@16
brew services start postgresql@16    # запомнит и будет стартовать сам
createdb neuro_db
```

**3. Окружение Python.**

```bash
cd ~/Desktop/Projects/Neuro
python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

**4. Туннель.**

```bash
brew install cloudflared
```

**5. Ключи.**

```bash
cp .env.example .env
```

Открыть `.env` и заполнить:

- `OPENAI_API_KEY` — ключ OpenAI;
- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather;
- `DATABASE_URL` — вместо `USER` подставить своё имя пользователя (узнать: `whoami`),
  `:PASSWORD` убрать, если пароля нет;
- `WEBAPP_URL` — **не трогать**, скрипт заполнит сам.

**6. Проверка.**

```bash
source venv/bin/activate
pytest -q                            # должно быть «264 passed»
```

**7. Запуск.**

```bash
./run.sh
```

Схема базы развернётся сама при первом старте бота.

## Что происходит при запуске

Скрипт печатает пять шагов. Если упадёт — скажет, на каком именно и что делать.

```
1/5  Проверяю окружение        venv, .env, PostgreSQL, cloudflared, свободный порт
2/5  Запускаю веб-сервис       и убеждается, что страница отвечает
3/5  Поднимаю HTTPS-туннель    ждёт адрес и проверяет его снаружи
4/5  Прописываю адрес          подставляет свежий адрес в .env
5/5  Запускаю бота             дальше окно занято ботом
```

Логи веб-сервиса и туннеля — в папке `logs/`. В git она не попадает.

## Важное про адрес карты

**Бесплатный туннель выдаёт новый случайный адрес при каждом запуске.**

Поэтому:

- ссылку на карту нельзя никому дать «навсегда» — завтра она будет другой;
- кнопка «🗺 Открыть карту» из вчерашней переписки **не сработает**, нужна свежая:
  нажмите «🧭 Практические рекомендации» ещё раз;
- пока ноутбук выключен или окно закрыто, карта не открывается ни у кого.

Профиль при этом **никуда не девается**. Он лежит в PostgreSQL и переживает
и перезапуск, и выключение компьютера. Карта всегда покажет последний итог,
даже если разговор был месяц назад.

Постоянный адрес требует либо аккаунта Cloudflare с именованным туннелем,
либо настоящего хостинга. Для портфолио это не нужно: витрина на GitHub Pages
живёт вечно и бесплатно.

## Как остановить

`Ctrl+C` в окне, где запущен скрипт. Он погасит туннель и веб-сервис
и сообщит об этом.

Скрипт гасит **только свои** процессы. Ничего постороннего на компьютере
он не трогает.

## Когда сломалось

### «Порт 8000 уже занят»

Что-то другое заняло порт — часто предыдущий запуск, закрытый неаккуратно.

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN     # посмотреть, кто это
PORT=8010 ./run.sh                   # или просто взять другой порт
```

### «PostgreSQL не отвечает»

```bash
brew services start postgresql@16
```

### Карта в Telegram не открывается

Почти всегда — умер туннель. Бесплатный туннель делает это молча: в логе
появляется `Unauthorized: Tunnel not found`, процесс продолжает висеть
и переподключаться, а адрес уже мёртв.

```bash
grep -i "tunnel not found" logs/tunnel.log
```

Лечится перезапуском: `Ctrl+C`, потом `./run.sh`. Адрес будет новый —
и кнопку в Telegram нужно получить заново.

### Бот отвечает «Пока рано: у меня ещё нет итогового синтеза»

Значит по этому человеку в базе нет ни одного завершённого разговора.
Пройдите разговор до конца и нажмите «✅ Подвести итог».

Если разговор точно был — проверьте, что бот смотрит в ту же базу:

```bash
grep DATABASE_URL .env
```

### Скрипт пишет «с этого компьютера адрес не открылся»

Свежий поддомен ещё не разошёлся по DNS вашего провайдера. С телефона обычно
работает — попробуйте открыть карту. Если не открылась, перезапустите скрипт.

### Туннель висит и не поднимается

В логе бесконечное `handshake did not complete in time` — сеть режет UDP.
Скрипт уже запускает туннель с `--protocol http2` именно поэтому. Если
не помогло — проверьте, не блокирует ли VPN или корпоративная сеть.

## Что где лежит

```
run.sh              запуск всего одной командой
.env                ключи и адрес карты. В git не попадает, никому не показывать
logs/               логи веб-сервиса и туннеля
docs/index.html     страница карты — она же витрина на GitHub Pages
docs/ROADMAP.md     что и почему делалось, со всеми разобранными ошибками
```

## Проверить, что всё цело

```bash
source venv/bin/activate
ruff check app core modules tests
pytest -q
```

Должно быть чисто и «264 passed». Те же проверки плюс сборка Docker-образа
гоняются на GitHub при каждом пуше.
