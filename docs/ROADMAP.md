# Roadmap — Neuro

Полный план доведения раннего MVP до чистого production-грамотного состояния,
пригодного как портфолио-проект на GitHub. Не переписываем всё с нуля: сохраняем
ценные идеи автора, убираем техдолг-мираж и мёртвый код, чиним боевые баги.

Рабочий процесс на каждом этапе: **audit → confirm → implement → test**.
Один этап за раз, не забегая вперёд. Принципы «сохранить любой ценой» и целевое
видение продукта — в [CLAUDE.md](../CLAUDE.md).

Целевая архитектура (слоистый монолит, честный):

```
app/ (Telegram I/O + Mini App backend)
  → core/orchestrator (один планировщик хода, без мнимой мультиагентности)
    → core/llm (OpenAI, structured outputs, retry/timeout)
    → modules/ (детерминированные детекторы: energy/compensation/role/team)
    → core/scoring (Big Five оси + пороги уверенности)
    → core/db/ (SQLAlchemy async → Postgres, + rehydrate состояния)
prompts/ (versioned, с evals позже)
webapp/ (Telegram Mini App: карта OCEAN + энергия)
```

вынесена в отдельный вопрос, в Этап 2 не входит.

### ✅ 2B — состояние

Закрыт, коммит `c5a4ce3`.

- Колонка `sessions.state_json` (JSONB), миграция —
  `migrations/001_add_sessions_state_json.sql`. Заведён каталог `migrations/`:
  `create_all` в существующую таблицу колонку не добавляет, Alembic пока не заводим,
  поэтому нумерованные идемпотентные `.sql`, применяются вручную.
  Восстановление из `messages`+`signals` отвергнуто — теряются `notes`, `goals`,
  `validity_level` по ходу и `synthesis_confirmed`, то есть флаг 2612-правила.
- **Rehydrate**: `_get_state` стал async, при пустой памяти поднимает последнюю
  `active`-сессию из БД. Битый или пустой снимок не роняет диалог — берётся чистое
  состояние, но та же сессия, чтобы не плодить брошенные `active`.
- **TTL-эвикция** `USER_STATES` (час без сообщений), без фонового таска.

Сделано сверх плана — разбор рисков:

- `finish_session` затирает `state_json`: снимок нужен только пока разговор живой,
  а это сырой психологический профиль. Итог к тому моменту уже разложен по
  `synthesis` / `signals` / `messages`.
- Колонка объявлена `JSONB(none_as_null=True)`. По умолчанию SQLAlchemy пишет
  питоновский `None` в JSON/JSONB как **литерал `null`**, а не SQL `NULL`: профиль
  стирается, но строка перестаёт находиться по `state_json IS NULL`. Поймано живой
  проверкой. **Те же грабли лежат под `synthesis.axes_confidence`,
  `synthesis.raw_json` и `akme.vector_json`** — они тоже пишутся `None` и тоже
  получают литерал; не трогал, вне задачи.
- Эвиктор не выбрасывает состояния без `session_id`: такие ни разу не доехали до БД,
  и rehydrate их не вернёт.
- `/start` и сброс кладут состояние мимо `_LAST_SEEN`, из-за чего эвиктор их не видел
  и они висели в памяти вечно — заведён `_put_fresh_state`.
- Забытый `await` у ставшего async `_get_state` — ошибка тихая. В `pyproject.toml`
  включено `filterwarnings = error` на `RuntimeWarning` **и**
  `PytestUnraisableExceptionWarning`: без второго не ловится, потому что предупреждение
  всплывает при сборке мусора уже вне теста. Проверено намеренно сломанным тестом.

Не чинилось осознанно: снимок пишется целиком каждый ход (~1 КБ на короткий диалог,
~20 КБ на длинный) тем же `UPDATE`, который и так выполнялся, — лишних запросов нет.
Хранить историю только в `messages` убрало бы дублирование, но дало бы риск
расхождения восстановленной истории с настоящей. Дублирование здесь покупает точность.

Verify: ✅ roundtrip состояния через JSON (включая `Axis`-ключи и `synthesis_confirmed`);
✅ эвикция по времени, неспасаемые состояния не выбрасываются; ✅ битый снимок не
роняет диалог; ✅ на живой `neuro_db` — сессия, история, сигналы, `validity_level`,
`notes`, `goals` и флаг 2612 переживают очистку памяти, снимок затирается при
завершении (тестовые строки удалены за собой).
