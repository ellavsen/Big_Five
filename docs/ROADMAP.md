# Roadmap — Neuro

Полный план доведения раннего MVP до чистого production-грамотного состояния,
пригодного как портфолио-проект на GitHub. Не переписываем всё с нуля: сохраняем
ценные идеи автора, убираем техдолг-мираж и мёртвый код, чиним боевые баги.

Рабочий процесс на каждом этапе: **audit → confirm → implement → test**.
Один этап за раз, не забегая вперёд. Принципы «сохранить любой ценой» и целевое
видение продукта — в [CLAUDE.md](../CLAUDE.md).

Целевая архитектура (слоистый монолит, честный):

```
app/ (Telegram I/O + Mini App backend)
  → core/orchestrator (один планировщик хода, без мнимой мультиагентности)
    → core/llm (OpenAI, structured outputs, retry/timeout)
    → modules/ (детерминированные детекторы: energy/compensation/role/team)
    → core/scoring (Big Five оси + пороги уверенности)
    → core/db/ (SQLAlchemy async → Postgres, + rehydrate состояния)
prompts/ (versioned, с evals позже)
webapp/ (Telegram Mini App: карта OCEAN + энергия)
```

## Этап 2 — LLM-слой и состояние `P1`

Разбит на три шага с отдельными коммитами: объём (8 файлов, миграция БД и смена
продуктового поведения) не откатывается одним куском.

Из плана выпал **prompt caching**: у OpenAI кэш включается сам на префиксах от ~1024
токенов, флага нет, системный промпт уже идёт первым — включать было нечего. Задача
«не слать 12 сообщений + состояние заново каждый ход» — это бюджет токенов, а не кэш;
вынесена в отдельный вопрос, в Этап 2 не входит.

### ✅ 2A — LLM-слой

Закрыт, коммит `a75f9f6`.

- `responses.create` + регексп-парсинг → `responses.parse(text_format=...)`.
- `timeout=30s`, `max_retries=3` (backoff даёт SDK), `max_output_tokens`,
  `temperature` — раздельно для хода диалога и синтеза.
- `SynthesisResult` переписан под strict-схему: открытые словари
  (`additionalProperties`) и `ge/le` API не принимает. `axis_map`, `axes_confidence`,
  `core_vs_role`, `akme_vector` — модели с фиксированными ключами,
  `probabilities` — список пар `{type, p}`.
- **Сверх плана**: живой вызов вскрыл инверсию оси EI (`1.0 = I`, тогда как у
  SN/TF/JP `1.0` = первая буква). LLM применяла общее правило — интроверт получал
  в `/akme` рекомендации для экстраверта. Пряталось за тем, что значения жались к 0.6,
  ровно к порогу `_dominant_letter`. Замер на 4 прогонах, ожидаемое ISFJ:
  было `ESFP/ESFP/ISFP/ESFP`, стало `ISFJ/ISTJ/ISTJ/ISFJ`.
- Промпт синтезатора приведён к новой схеме; полярность осей задокументирована;
  `axis_map` описывает наблюдаемое поведение целиком, разделение ядро/роль — в
  `core_vs_role`; `message` разбивается на 3–5 абзацев.
- Тесты 32 → 42, `ruff` чистый.

Verify: ✅ нет регексп-парсинга JSON; ✅ тесты на таймаут и на пустой ответ модели;
✅ живой вызов принят API.

### ⬜ 2B — состояние

- Колонка `sessions.state_json` (JSONB) + `ALTER TABLE`: `create_all` в существующую

  теряются `notes`, `goals`, `validity_level` по ходу и `synthesis_confirmed`,
  то есть флаг 2612-правила.
- **Rehydrate состояния** при входящем сообщении + TTL/эвикция для `USER_STATES`.

Verify: roundtrip-тест сериализации состояния; тест эвикции по времени;
рестарт процесса не теряет активный диалог.

### ⬜ 2C — закрытие осей

- **Переделать закрытие осей**: сейчас `any(s.direct_example)` закрывает ось, а модули
  ставят `direct_example=True` по одному вхождению подстроки — «хочется» закрывает TF,
  «расслаб» закрывает SN, «контрол» закрывает JP. Ввести накопление веса по
  направлению, порог суммы confidence, ≥2 источников и проверку перевеса над
  противоположным полюсом. Образец правильного поведения — `team_mirror`, он ставит
  `direct_example` только при маркере эпизода.
- `soft_axis_closed` обещает в докстринге «≥2 **согласованных**», а в коде просто
  `len(signals) >= 2` — согласованность не проверяется.
- `energy_economy` пишет `source="module"` вместо `"energy"`, из-за чего ветка
  `confidence="high"` в `modules/synthesizer.py` мертва.
- Русский матчинг: **учёт отрицаний** («не контролирую» ≠ контроль) общим хелпером.
  Лемматизация (pymorphy3) осознанно отложена: модули матчат по основам («контрол»,
  «устал»), это уже покрывает большую часть словоформ, выигрыш поверх — небольшой.
- Из 2A: LLM **переотправляет сигналы, уже лежащие в `evidence`**, дословно — накрутит
  счётчики в `soft_axis_closed` и `is_profile_sufficient`.
- Из 2A: `axes_confidence` почти не разъезжается по осям (0.6–0.7 везде) даже с
  якорями в промпте; TF пляшет 50/50 на смешанном материале при уверенности 0.65.

Verify: тест, что одно слово ось не закрывает; тест «не контролирую» ≠ сигнал J;
дубли сигналов не двигают закрытие осей.
